# News reader

A web page that lists headlines about politics in Sweden from a few owner-approved sites (today SVT and Sveriges Radio). The build already collects the headlines of all four topics (Alla nyheter, Politik, Natur, AI) from SVT into `news.json` (F5); until the topic choice of F7 the page still shows politics only. Each item shows the headline, the source, the publication time and a link to the original article. The page text and the news are in Swedish.

Status: skeleton (S2) plus the RSS parser and headline cleaning of the build (S4), time handling (S5), the shared keyword list with keyword matching (S6), item selection with the final item shape (S7) and the build command with `news.json` (S8). F3 adds `sources.json` version 2 (topics and several feeds per source). The JavaScript twin of the build logic, `site/logic.js`, is done (S9). The page, part 1 (S10: SVT headlines, the choice of sources, offline copy, notices) and part 2 (S11: the Sveriges Radio live fetch in the reader's browser) are done. F4 adds one keyword file per topic (`politics-keywords.json` in version 2, `nature-keywords.json`, `ai-keywords.json`), the matching of `include.phrases` and `include.caseSensitiveWords`, shared cases per topic and the function that returns all topics of an item (`topics_of`, `topicsOf`); the build uses all lists since F5, the page still only the Politik list until F7 and F8. F5 makes the build write `news.json` version 2: every item lists its `topics`, there is one status per source and per feed, each distinct feed address is fetched once, the 24-hour fallback works per feed, and the build loads and checks every keyword file that `sources.json` names; the page reads version 1 and 2 and shows the Politik items only. See the [design](news-reader-design.md) for the goal, requirements, architecture and step plan.

## Files
- `sources.json` (version 2 since F3, design section 7.5): the approved sources and the topics. `topics` lists `all-news` "Alla nyheter", `politics` "Politik", `nature` "Natur" and `ai` "AI" in this order; each topic except `all-news` has `keywords`, the name of its keyword file (`<id>-keywords.json`; `validate_sources` checks the name, the build loads and checks the file, see below). Each source has `id`, `name`, `enabled`, `fetchedBy`, `storageAllowed`, `homepage`, `allowedHosts`, the optional `credit` and `linkHosts` (used by Riksdagen in F6, accepted and validated now), and `feeds`: a list with one entry per topic the source offers, each with `topic`, `method` (`feed`, `categoryFilter` or `keywordFilter`; `all-news` only `feed`), `url` (https; for a build source on its `allowedHosts`) and an optional `matchOn` (`title`, only with `keywordFilter`). Feed entries may share an address; the build fetches each distinct address once. SVT is collected by the build (`fetchedBy: build`, may be stored): `nyheter/rss.xml` for Alla nyheter, Natur and AI, `nyheter/inrikes/rss.xml` for Politik. Sveriges Radio is fetched live in the browser (`fetchedBy: browser`) and must never be stored (`storageAllowed: false`): program 83 for all four topics. Since F5 the build evaluates every feed entry (all four topics); the page (`validateSources`, the live fetch) still uses only the feed entry of the topic `politics` until F8. A file of version 1 is refused by the build with the message "sources.json version 1 is no longer supported" (the build fails and writes nothing, R14.6) and silently by the page (`validateSources` returns null, so the page shows its generic failure text "Kunde inte hämta nyheter. Försök igen senare."); the page cannot tell the number 2.0 from 2, because JSON gives it the same value, while the build rejects a non-integer version; the validation is `validate_sources` in `newsreader/build.py` and `validateSources` in `site/app.js`. Changes only through issues approved by the owner.
- `politics-keywords.json`: the one shared keyword list that decides which items are about Swedish politics (R4.3). The Python build reads it, and the page will fetch the same file (S9), so there is no second copy of the terms. Shape (design sections 7.2 and 7.6, the same for every topic file since F4, see the next two entries): `version` (2; version 1 with `category` is no longer accepted), `topic` (`politics`), `include.words` (single words, written lower case in the file; capitals as in design 7.2 are also accepted and lowercased by the loader, a trailing `*` makes a prefix term), `include.caseSensitive` (exact substrings such as `(SD)`, case kept), `exclude.words` (words that never count, for example `moderat`) and `exclude.phrases` (phrases of two or more words, for example `tyska regeringen`, removed before matching), plus the two kinds of terms added in F4, `include.phrases` and `include.caseSensitiveWords` (both empty in this file). `minister`, `val` and `parti` are not include terms on purpose (too broad). Changes only through issues, when false positives or negatives are found (K6).
- `nature-keywords.json` (F4, R17.1): the keyword list of the topic Natur: nature and environment, climate, animals and weather events, in Swedish. It uses specific terms and no broad prefixes (K15): for example `naturreservat*`, `nationalpark*`, `naturvård*`, `klimatförändring*`, `växthusgas*`, `rovdjur*`, `skogsbrand*`, `översvämning*`, `oväder*`, `smhi`, the exact words `natur`, `naturen` and `torkan`, and the phrases `biologisk mångfald`, `global uppvärmning` and `vilda djur`. `exclude.phrases` take out the figurative uses `politiska klimatet` and `ekonomiska klimatet`. Bare `storm`, `stormen`, `stormar`, `stormarna` and `torka` are not terms ("Stormen i regeringen", "Storm av kritik", "torka tvätten"); only `stormvarning*`, `snöstorm*`, `oväder*`, `orkan*` and the like count. Changes only through issues.
- `ai-keywords.json` (F4, R17.2, D23): the keyword list of the topic AI, in Swedish and English. The short term `AI` is in `include.caseSensitiveWords`: a whole word in exactly this case, so `AI-regler` and `Ny AI-lag` match, while `AIK`, `FAIR`, `AI2`, `Ai Weiwei` and a lower-case `ai` do not (`LLM` and `LLMs` are handled the same way). The other terms are `include.words` (`chatgpt`, `openai`, `anthropic`, `chatbot*`, `språkmodell*`, `maskininlärning*`, `djupinlärning*`, `deepfake*`, `neuronnät*`) and `include.phrases` (`artificiell intelligens`, `artificiella intelligensen`, `artificial intelligence`, `machine learning`, `deep learning`, `language model`, `language models`, `neurala nätverk`, `neural network`, `neural networks`). `KI` is left out on purpose (K16). Its exclude lists are empty: an exclusion never applies to case-sensitive words (R17.3), and none of the other terms needed one.
- `newsreader/`: the Python build, standard library only. Since F5 `build.py` fetches each distinct feed address once and evaluates every feed entry on the response with `topics_of` (see "Run the build locally"); `model.py` has `TopicItem`, the item of `news.json` version 2 (the seven fields plus `topics`); `select.select_items` is still the one-topic selection (politics) and is no longer called by the build, `select.sort_items` is the shared order. So far: `model.py` (`RawEntry`: title, link, time text, description), `parse.py` (`parse_rss`: RSS 2.0 bytes to raw entries) and `select.py` (`clean_headline`, R1.3, and the item selection, see below) and `timeutil.py` (time handling, R2, see below) and `keywords.py` (keyword list and matching, R4.4, see below). `parse_rss` decodes by the XML declaration (UTF-8, ISO-8859-1), refuses a response over 2 MB, refuses documents that declare any entity (the XML parser itself rejects the declaration, so no external entities are resolved), and accepts only UTF-8 and ISO-8859-1 (UTF-16, UTF-32 and any other declared encoding are refused), and raises `FeedError` for empty, malformed or non-RSS documents (the root must be `<rss>`). Items with no title, link, time and description are skipped; other items are kept raw, with an empty string for a missing field. Dropping items with an empty headline or an unusable link is done later by the selection step.
- `tests/shared-cases.json`: cases shared by the Python and JavaScript tests, with the sections `cleaning`, `time`, `keywords` and (F4) `topics` (all filled). Each case has `id`, `input` and `expected`; a `keywords` case has `input` `{topic, headline, description}` (`topic` is `politics`, `nature` or `ai` and a missing `topic` means `politics`; `description` may be missing, `null` or empty) and `expected` `{match}` (true or false); a `topics` case has `input` `{headline, description, feeds}` (`feeds` are the feed entries of one feed URL, `{topic, method, matchOn?}`) and `expected` is the list of topic ids in the order of R13.1; a `time` case has `input` `{text, now}` (the feed's time text or `null`, and the "now" of the build as UTC text) and `expected` `{published, publishedDisplay}`. Headline cleaning is defined with fixed sets so that the JavaScript version (S9) can reproduce it exactly and does not depend on any library table:
  - Tags: `<` followed by a letter or `/` up to `>`, and `<!-- ... -->` comments, are removed (`a < b` is not a tag).
  - Entities are decoded once, in one pass: `&amp; &lt; &gt; &quot; &apos;`, numeric references (decimal and hex, any number of digits) for code points from 1 to U+10FFFF except surrogates (U+D800 to U+DFFF), and the named list `&nbsp; &laquo; &raquo; &ndash; &mdash; &hellip; &lsquo; &rsquo; &ldquo; &rdquo; &auml; &ouml; &aring; &Auml; &Ouml; &Aring; &eacute; &Eacute; &euro; &copy;` (case-sensitive). Everything else is left exactly as written: entities without a semicolon, other names, `&#0;`, surrogates, values above U+10FFFF. `&#128;` is the plain control character U+0080, not the euro sign.
  - White space is exactly U+0020, tab, LF, CR, FF, VT and U+00A0 (no-break space): runs become one space and leading and trailing ones are removed. The JavaScript version must use this explicit set, not `trim()` or `\s`. Other Unicode spaces are kept.
- Time handling (`newsreader/timeutil.py`, R2): `published_utc(text, now)` turns the feed's time text into `YYYY-MM-DDTHH:MM:SSZ` or `None`; `display_time(published)` gives `YYYY-MM-DD HH:MM` in Europe/Stockholm, or `Tid saknas` for `None`; `generated_at(now)` and `generated_at_display(now)` give the two fields of R2.7. `now` is always passed in (an aware datetime), never read from the clock. Rules, written out so that S9 can copy them:
  - Accepted: RFC 822/2822 (`Fri, 13 Nov 2026 14:05:00 +0100`; the weekday is optional and not checked; seconds optional; the zone is `+HHMM`, `-HHMM` or one of `UT UTC GMT Z EST EDT CST CDT MST MDT PST PDT`) and ISO 8601 `YYYY-MM-DDTHH:MM[:SS]` with `Z` or an offset `+HH:MM`, `+HHMM` or `+HH` (a fraction of a second is ignored, not rounded). Digits are ASCII only. An ISO time with a space instead of `T` (`2026-11-13 12:00:00`) gives `null`. The year must be 1970 to 9998 (checked on the parsed fields before any conversion); any other year gives `null`, so no input can overflow `datetime`. Leading and trailing white space is ignored. Any other text, other zone names (for example `CET`), a date without a time, or an impossible date or time (32 November, 29 February in a non-leap year, hour 24, minute 60, second 60) gives `null`.
  - No zone: read as Europe/Stockholm wall-clock time. The two hours around the switches are resolved like this: a local time that does not exist (02:00 to 02:59 on the last Sunday of March) uses the winter offset +01:00, so `02:30` is `01:30Z` and is shown as `03:30`; a local time that exists twice (02:00 to 02:59 on the last Sunday of October) is read as the first occurrence, the summer offset +02:00, so `02:30` is `00:30Z` and is shown as `02:30`. UTC instants are shown exactly (`2026-10-25T01:30:00Z` is the second `02:30`).
  - A time more than 10 minutes after `now` is `null` (exactly 10 minutes is kept). `published` is always whole seconds in UTC.
  - Note for S9 (done: `site/logic.js` does not use `Intl` at all, it writes the Stockholm rules out as described under `site/logic.js` below; the note is kept as the original reasoning): the JavaScript version must give the same text. `Intl.DateTimeFormat("sv-SE", {timeZone: "Europe/Stockholm", hourCycle: "h23", ...})` can supply the parts (year, month, day, hour, minute), which are then joined by hand into `YYYY-MM-DD HH:MM` (do not rely on the locale's own separators; `hour12: false` can give `24:00` in some engines, so use `hourCycle: "h23"`). For a time without zone, Intl cannot parse local time, so use an explicit rule: guess the UTC instant from the fields, find the Stockholm offset (+1 or +2 hours; summer time runs from 01:00 UTC on the last Sunday of March to 01:00 UTC on the last Sunday of October), and apply the gap and repeated-hour rules above. Use the same ASCII-digit regular expressions as `timeutil.py` (Python's `\Z` is JavaScript's `$` without the `m` flag), and never format with a library that does not zero-pad years (`timeutil.py` pads every field by hand). `Date.UTC` reads the years 0 to 99 as 1900 to 1999, which is a non-issue because the year range rule rejects those years first and build dates with `Date.UTC` plus an explicit range check (`Date` accepts 32 November and rolls it over). All shared `time` cases must pass.
  - `zoneinfo` needs a time zone database. On Linux, macOS and the `ubuntu-latest` runner of `ci.yml` the system database is used. A machine without one (typically Windows without the `tzdata` package) fails with `ZoneInfoNotFoundError`; if that happens run `python -m pip install tzdata`. `tzdata` is not in `requirements.txt` because CI does not need it.
- Keyword matching (`newsreader/keywords.py`, R4.4, R13.4, R17): one list per topic, chosen by name. `load_topic_keywords("nature")` reads `nature-keywords.json` (also `politics` and `ai`; `all-news` has no list) and `load_keywords(path=None, topic=None)` reads any one file (default `politics-keywords.json`; with `topic` the file must belong to that topic). Both return a `Keywords` object; `.matches(headline, description=None)` gives true or false for that topic. `topics_of(headline, description, feeds, keywords_by_topic)` returns all topics of one item in one call, in the order of R13.1 without duplicates (F5 and F8 use it): a `feed` entry gives its topic, a `keywordFilter` entry gives it when that topic's list matches (with `matchOn` `title` the description is not read), `categoryFilter` is not supported. It takes the RAW headline and description as the feed gave them and cleans each of them once itself, reusing the result for every `keywordFilter` entry, with the same outcome as `matches` (`matches_cleaned` is the shared inner step); the caller (F5, F8) must not clean them first, because cleaning twice can change a text. An item can match no topic when its feed has no `feed` entry. `KeywordsError` (a `ValueError`) is raised for an invalid file, so the build (S8) fails as R6.4 says: wrong or extra keys, wrong version or a `topic` that is not the expected one, a term that is empty, has surrounding white space, or is duplicated (the error names the term; duplicate JSON keys are named too), a `caseSensitive` term that is not NFC, a `words` term that is not one word, a wildcard anywhere but at the end, an exclude phrase that is not two or more words separated by single spaces. The description is only read for matching and is never returned or stored. Rules, written out so that S9 can copy them exactly:
  - Term normalisation: terms in `include.words`, `exclude.words` and `exclude.phrases` may be written with capitals; the loader makes them NFC and then lower case, and finds duplicates after that (`Riksdag*` next to `riksdag*` is an error). `include.caseSensitive` terms are kept exactly as written. The S9 loader must do the same: `normalize("NFC")`, then `toLowerCase()`, duplicates checked after lowercasing.
  - Headline and description are each cleaned with `clean_headline` first and tested separately; a hit in either is a match. A missing, `null` or empty description is ignored.
  - The cleaned text is NFC-normalised and split into words: maximal runs of Unicode letters (category starting with L) and decimal digits (Nd). So `-`, `_`, `/`, spaces and punctuation split words, while å, ä, ö and any other letter or digit next to a term make it a different word. Each word is lowercased.
  - An `include.words` term matches a whole word; a term ending in `*` matches every word that starts with the term without the `*` (`riksdag*` matches `riksdagsledamot`, but not `vårdriksdagen`; `rosenbad` does not match `rosenbadet`).
  - `exclude.phrases`: every place where a phrase's words follow each other is marked, and the marked words are taken out together before matching (so a headline with `tyska regeringen` and `riksdagen` still matches, and overlapping or adjacent phrases behave the same everywhere). A phrase never spans the headline and the description.
  - `exclude.words`: a word equal to one of them never counts as a hit (`moderat` and `moderata`; `Moderaterna` and `moderatledaren` still match). The official name "Moderata samlingspartiet" is therefore not matched, as the design accepts.
  - `include.caseSensitive` terms are exact substrings of the NFC-normalised cleaned text, case and brackets kept (`(SD)` matches, `(sd)` and `[SD]` do not). Exclude phrases and words do not affect them. The other terms are lowercased when the file is loaded, so only these keep their capitals.
  - `include.phrases` (F4, R17.3): two or more words separated by single spaces, no `*`, written lower case; a phrase hits when its words follow each other in the lower-case word list, at positions none of which was marked by an exclude phrase. Exclude words do not apply to include phrases. Validation: two or more words, duplicates after lowercasing are an error.
  - `include.caseSensitiveWords` (F4, R17.3): each term is exactly one word (letters and digits, at least one letter, no `*`, NFC, no surrounding white space) and matches a word of the NFC-normalised text with the case kept, so `AI` matches `AI-regler` but not `AIK`, `FAIR`, `Ai` or `ai`. No exclusion applies to them, as for `caseSensitive`.
  - At least one of the four include lists must be non-empty; all keys of the file are required, lists may be empty.
  - Exclusion never drops a whole item; it only takes words and phrases out of consideration.
  - Note for S9: use `[\p{L}\p{Nd}]+` with the `u` flag for the words (not `\w`, `isalpha`-like tests or `\b`), `String.prototype.normalize("NFC")` before splitting, `toLowerCase` on each word, plain `includes` for the case-sensitive terms and a word-by-word comparison for the phrases (no regular expression built from the terms). Python and JavaScript may differ for characters added in newer Unicode versions; the shared `keywords` cases must pass in both. Validate the file in the page the same way (or at least in the build, which fails on an invalid file).
- Known limits (K6): the list is approximate. Accepted for now and handled by follow-up issues:
  - False negatives: possessive party names (`Centerpartiets`), abbreviations without brackets (`M-ledaren`, `SD kräver`), headlines that name only a person or a minister, and `Valet 2026` (`val` is not an include term).
  - False positives: foreign governments outside the phrase list (`Spanska regeringen`, `Norges regering`, `USA:s regering`) and brackets used for other things (`Storlek (L)`).
- Known limits of the new lists (K15, K16). The lists are approximate and are tuned through issues after the owner and F5 have read live feeds:
  - Natur, false negatives: `klimatpolitik`, `klimatmål` and other compounds of `klimat` are not terms (a prefix `klimat*` was not chosen: it would put most political headlines about climate policy under Natur too), so a headline about climate policy usually belongs to Politik only; only the exact forms listed are matched (`vargen` but not `vargens`, `björnen` but not `björnens`; `varg` and `björn` alone are left out because of names such as Björn and Vargas); English text is not covered; weather without a listed word (`snöfall`, `värme`, `regn`) is not matched; suffix compounds are missed because a term matches a whole word or a prefix only (`snöoväder`, `åskoväder`, `vinterstorm`, `höststorm`).
  - Natur, false positives: `natur` can be part of a name (`Natur & Kultur`), `koldioxid*` and `älg*` also match unrelated compounds, and a passing mention of a listed word in the description counts when the feed has no `matchOn` `title`.
  - AI, false negatives: `AI` is matched only in capitals, so a lower-case `ai`, the dotted form `A.I.` and the Swedish short form `KI` are never matched; headlines about a product without a listed word (`Gemini`, `Claude`, `Copilot`, `algoritmer`, `robotar`) are not matched; Swedish inflections of the phrases other than `artificiella intelligensen` are not (a phrase has no prefix form).
  - AI, false positives: `AI` as the abbreviation of Amnesty International ("Amnesty (AI)"), a headline written in capitals that contains the word `AI`, `LLM` as the degree Master of Laws, and a passing mention in the description. Exclusions cannot remove a case-sensitive hit (R17.3).
  - Politik: unchanged (K6). An item can match several topics (`Regeringen testar AI mot översvämning` belongs to Politik, Natur and AI); that is intended (R13.3).
- Item selection (`newsreader/select.py`, R1.1, R1.4, R5.1 to R5.4, R9.1): `select_items(entries, source, keywords, now)` turns the raw entries of one source (`source` is its entry in `sources.json`, `now` an aware datetime, never read from the clock) into a list of `NewsItem` (`model.py`), which has exactly the seven fields of R1.1 (`id`, `sourceId`, `sourceName`, `title`, `url`, `published`, `publishedDisplay`; `as_dict()` gives the form for `news.json`). The description is used for the keyword filter only and is dropped. A source is filtered by keywords when the `method` of the `politics` feed entry (`feed_entry(source, "politics")`) in `sources.json` is `keywordFilter` (a `feed` source is not filtered; `categoryFilter` raises `ValueError` until raw entries carry categories). Disabled sources and browser sources are not handled here (S8). From F5 the build does not call `select_items`: `build.build_source` applies the same rules per feed entry and per topic (see "Run the build locally"); `select_items` stays as the one-topic version, tested on its own. Rules, written out so that S9 can copy them:
  - Order of the steps: clean the headline (empty drops the item), keyword filter, URL check, de-duplicate, age limit, sort, cap of 20.
  - URL check (`parse_url`, `check_url`): white space around the text is ignored; the rest may only hold the printable ASCII characters U+0021 to U+007E (so no inner white space, control characters, raw IDN or other non-ASCII; punycode `xn--` is plain ASCII) and no backslash. The scheme is `http` or `https` (any case). The authority may not hold `@` (`https://svt.se@evil.com/`), a port (even the default one) or a trailing dot, and the host must be lower-cased dot-separated labels of `a-z 0-9 -`. The host must equal an `allowedHosts` entry or end with `.` plus one (`www.svt.se` yes, `evilsvt.se` no). No `urllib` is used, because its leniency differs between languages. The item keeps its URL as in the feed (trimmed).
  - Normalised URL (R5.3, used for duplicates and the `id`): lower-case scheme and host, one leading `www.` removed from the host, query and fragment removed, all trailing `/` removed (`https://svt.se/` is `https://svt.se`). The path keeps its case and is not percent-decoded; `http` and `https` stay different. Duplicates are found per source after the other drops, and the first one in feed order is kept.
  - `id` (R5.4): the first 16 hex characters (lower case) of the SHA-256 of the normalised URL as UTF-8.
  - Age (R5.2): `published` older than 7 days before `now` is dropped, exactly 7 days is kept. An item without time (or with a bad or future time, which gives `null`) is kept.
  - Order and cap (R5.1, R5.5): newest `published` first, items with `null` last; equal times by title compared by Unicode code point (JavaScript must compare code points, not UTF-16 units), then feed order; the first 20 are kept, so undated items only fill the free places.
  - The shared cases file has no `selection` section: design section 9 keeps the three sections `cleaning`, `time` and `keywords` there, and the JavaScript side tests selection with its own plain-object tests in S9. The URL lists in `tests/test_selection.py` (`GOOD_URLS`, `BAD_URLS`) are meant to be reused as the S9 test data.

- `site/logic.js` (S9): the pure logic of the page, the JavaScript twin of `select.py`, `keywords.py` and `timeutil.py`. No DOM, no network, no storage, no clock (`now` is always a parameter: a `Date`, epoch milliseconds, or UTC text like `2026-11-13T13:05:12Z`), no dependencies. It is a classic script that also works under Node (not an ES module: a page loads it with `<script src="logic.js">` and uses the global `NewsLogic`; Node uses `require` or `import logic from "./logic.js"`; do not add `"type": "module"` to a `package.json` above it). Functions:
  - `cleanHeadline(text)`: tags removed, the fixed entity set decoded once, the white space set ` \t\n\r\f\v` and U+00A0 (not `trim()` or `\s`).
  - `validateKeywords(parsedJson, topic)` (same checks and normalisation as `load_keywords`; the page fetches a keyword file, parses it and passes it in; with `topic` the file must belong to that topic; a duplicate JSON key cannot be seen after `JSON.parse`, the Python side rejects it) and `matchesKeywords(keywords, headline, description)`; `keywordFileName(topic)` (`<topic>-keywords.json`), `TOPIC_ORDER`, `KEYWORD_TOPICS`; and `topicsOf(headline, description, feeds, keywordsByTopic)`, the twin of `topics_of` (raw texts, cleaned once inside) (`keywordsByTopic` is a plain object or a `Map` of topic id to the result of `validateKeywords`). `selectItems` is unchanged in F4: it still takes one keyword object.
  - `checkUrl(url, allowedHosts)` (normalised URL or `null`; same rules as `check_url`), `parseUrl`, `itemId(normalisedUrl)` and `sha256Hex(text)` (a small synchronous pure-JS SHA-256, so it works in Node and browsers without `crypto.subtle`).
  - Time: `publishedUtc(text, now)`, `displayTime(published)`, `parseTime`, `formatUtc`, `generatedAt(now)`, `generatedAtDisplay(now)`. Europe/Stockholm is written out, not read from `Intl`, so Node and every browser give the same text: no summer time in 1970-1979; in 1980 from 6 April; from 1981 from the last Sunday of March; ends the last Sunday of September until 1995 and of October from 1996; changes at 01:00 UTC; years 1970 to 9998 as in Python. A local time in the skipped hour is read as +01:00, a repeated hour as the first occurrence (+02:00). These are the rules Python's `zoneinfo` gives (checked for every year 1970 to 9998). `displayTime` throws `Error` for text that is not a UTC time, like Python's `ValueError`.
  - Where JavaScript is not identical to Python (known and accepted): `displayTime` shows times before 1970 with +01:00 (Python uses local mean time before 1893 and so on), which parsed input can never reach (a parsed time is at most one day before 1970). Node and Python can ship different Unicode data versions, so for very new characters the word class (`\p{L}`, `\p{Nd}`), NFC and lower-casing can differ. `validateKeywords` cannot tell `1.0` from `1` in `version` because `JSON.parse` gives the same number. A selected item whose time is before the 7 day limit is dropped, also when the time is before 1970 (Python's `select_items` does not handle that case). An Atom `published` that is only white space falls back to `updated`. All text trimming is done with linear scans, so very long inputs are handled quickly.
  - `selectItems(entries, source, keywords, now)`: the steps of `select_items`, returning items with exactly the seven fields of R1.1. An entry is a plain object: `title`, `link`, the time as `timeText` (Python shape) or `published` falling back to `updated` (Atom, used when `published` is missing or empty), the description as `description` or `summary`; `content` is never read.
  - `mergeItems(listsOfItems)` merges the items of several sources and sorts them (R5.5): `published` newest first, `null` last, equal times by `sourceId`, then `title` (compared by Unicode code point), then the order given; nothing is de-duplicated across sources. `sortItems(items, bySource)` is the sort alone.
- `site/index.html`, `site/app.js`, `site/style.css` (S10): the page. `index.html` is the Swedish skeleton (`lang="sv"`, `noindex`, a Content-Security-Policy meta tag that only allows the page's own scripts, styles and requests, no inline script or style). `app.js` is a thin classic script that loads `sources.json` and `news.json` from its own folder, validates them (types, sizes, links through `NewsLogic.checkUrl`, time text recomputed by `NewsLogic`), merges and sorts with `NewsLogic.mergeItems` and writes the DOM with `createElement` and `textContent` only. Since F5 `validateNews` reads `news.json` version 1 and 2 (any other version is refused) and returns a clean copy in the shape of version 2: every item has `topics` (a version 1 item gets `["all-news", "politics"]`; a version 2 item whose `topics` is missing, empty or has no known id is dropped), `topics` of the file and the status of each feed are kept, and a Sveriges Radio item is never read from a file. `visibleItems` shows only the file items whose `topics` contain `politics` until the topic choice of F7 (R19.8), so the list is the one it was before; live items have no topics and are all shown. The offline copy `newsReader.lastNews` is the clean copy (version 2, all topics); a copy that an older page saved (version 1) is shown whole. The row of a build source in "Källor" uses, for a version 2 entry, the status, `lastSuccess` and `itemCount` of its `politics` feed (so "Hämtad, N rubriker" counts the headlines shown, and a failure of only the broad feed does not turn the row into "Kunde inte hämtas"); an entry without `feeds` (version 1) uses the source-level fields (R19.8). F7 switches to per-topic counts. It shows headline, source name, time and link for each item (links open in a new tab with `rel="noopener noreferrer"`), the section "Källor" (a labelled check box per enabled source with the note "Urval med nyckelord – ungefärligt" and the source's status), the notices (offline copy, stale data, empty choice, failed load) and the bottom line with the source names from `sources.json`. Loading: when the page opens, every 10 minutes while the tab is visible, and on "Uppdatera"; a failed load keeps what is shown. localStorage: `newsReader.selectedSources` (the chosen source ids; all sources on the first visit, and when storage is blocked) and `newsReader.lastNews` (the last good `news.json`, version 2, build sources only, validated again when read). Every storage access is in try/catch and the page works without it. A reload that brings the same data does not touch the list or the notices (so the keyboard focus stays, and a screen reader does not read an unchanged notice again); when the list does change, the focus stays on the same headline if it is still there. The "Uppdatera" button is marked busy with `aria-busy` while loading, never disabled. The button and "Källor" are hidden without JavaScript, and "Källor" stays hidden until `sources.json` has been read. If `sources.json` cannot be read, the saved copy is not shown either (the page has no list of allowed hosts to check its links against; nothing unvalidated is trusted), and the page says "Kunde inte hämta nyheter. Försök igen senare." No service worker, no Cache API, no requests to other sites. The Sveriges Radio live fetch (S11) is described under `site/atom.js` below. `app.js` also works under Node (`require`), exporting its pure parts for the tests.
- `site/atom.js` (S11): the Atom side of the live fetch of a `fetchedBy: browser` source (today Sveriges Radio), with no rendering, no timers and no storage. `fetchAtom(fetch, url, {signal})` sends the request with `credentials: "omit"`, `cache: "no-store"` and `referrerPolicy: "no-referrer"` (the address of the page is not sent; nothing else is set except the abort signal), accepts only status 200, reads the body with a limit of 2 MB that is checked against `Content-Length` and while the stream is read, decodes it by the charset of the response (UTF-8 if none), and gives it to `parseAtom`. `parseAtom(text)` refuses a text over the limit, refuses any `<!DOCTYPE` or `<!ENTITY` before parsing (an Atom feed has none), parses with the browser's `DOMParser` as `application/xml`, refuses a document with a `<parsererror>` or a root that is not the Atom `<feed>` (Atom namespace), and maps at most 100 `<entry>` elements to plain objects with exactly `title`, `summary`, `link`, `published`, `updated` (strings, empty when missing). The link is the first `rel="alternate"` (or no `rel`) link with a `href`; `<content>`, `<author>`, `<id>` and `<category>` are never read. A headline is never cut: a title over 5000 characters becomes empty and the entry is dropped; a summary over 20000 characters is ignored (it is only used for the keyword match). Every failure is an `AtomError` with a fixed message and one of the kinds `network`, `timeout`, `status`, `too-large`, `dtd`, `parse`, `not-atom`; nothing from the feed or from the original error is in it.
- The live fetch in `site/app.js` (S11): the page fetches `politics-keywords.json` (the one shared list, R4.3) and, for each enabled source with `fetchedBy: browser`, the feed address in `sources.json` (it is not written in `app.js`; only `https` is accepted). The plain entries go through `NewsLogic.selectItems` (clean, keyword match on headline and summary, link check against the source's `allowedHosts`, de-duplicate, time, 7 days, 20 newest), so a Sveriges Radio item has exactly the seven fields of R1.1 and the summary is dropped. The items are kept in `state.live` (a variable) only. Nothing about them is passed to the code that writes `localStorage`: the saved copy `newsReader.lastNews` is made from the validated `news.json` (SVT only) and a test checks that it holds nothing from Sveriges Radio after a successful fetch. No `sessionStorage`, IndexedDB, cookie, Cache API or service worker is used, and the page writes nothing to the console. Call limits (R7.2, the rule is `NewsLogic.liveFetchAllowed`): one request when the page opens (if the tab is hidden then, when it becomes visible); then at most one every 10 minutes from the timer (the first request of a page is stamped a little after the timer starts, so the timer may count 10 minutes minus 30 seconds; this tolerance is for the timer only and the 5-minute rule is unchanged) or when the tab becomes visible again (a full 10 minutes since the last request); "Uppdatera" reloads SVT at once and fetches Sveriges Radio only if at least 5 minutes have passed since its last request; nothing is sent while the tab is hidden; **a source the reader has unticked is not requested at all** (not on load, timer, "Uppdatera" or visibility, and not even its keyword list), and any items of it are dropped from memory; its row in "Källor" says "Inte vald – ingen hämtning" (wording chosen here, the design has none); when the reader ticks it, it is fetched at once if the 5-minute rule allows (always for the first request of the page load), otherwise nothing is held or shown and the status is "Inte hämtad ännu" until the next allowed request; ticking some other source never fetches it; a request that is still running is never repeated; the time of a request is noted before anything is awaited. A failed request is not retried before the next allowed time. The request has a timeout of 15 seconds. SVT and Sveriges Radio are loaded independently: a slow or failing Sveriges Radio never delays or hides SVT items, and the reverse. The status in "Källor" is "Hämtar …", "Hämtad 14:07, 3 rubriker" or "Sveriges Radio kunde inte hämtas just nu" (R7.6); after a failure the items from the earlier request are removed (nothing old is shown without a limit), and the line at the top adds "Sveriges Radio hämtad 14:07" after a success. Every item shows its source name. The Content-Security-Policy of `index.html` allows `connect-src 'self' https://api.sr.se` and nothing else beyond what S10 had.
- `site/tests/atom.test.mjs`, `site/tests/live.test.mjs`, `site/tests/xml-fake.mjs`, `site/tests/fake-page.mjs` (S11): `node --test` for `atom.js` (parsing, the fallback from `published` to `updated`, links, entities, CDATA, namespaces, hostile and oversize input, the shared keyword cases run through XML, the request and its failures) and for the live fetch of the page (call limits with a fake clock and fake `fetch`, hidden tab, overlapping requests, failure statuses with the SVT items still shown, a console spy, spies on every kind of storage, cookies and the Cache API, and the merge). Node has no `DOMParser`, so these tests use `xml-fake.mjs`, a small stand-in; the real `DOMParser` is checked in a browser by hand (below). The two helper files are not tests themselves.
- `site/tests/app.test.mjs`: `node --test` for `app.js`: validation of `sources.json`, `news.json`, the saved copy and the saved choice, the notices and the rows of "Källor", the whole page against a small hand-written fake DOM and fake `fetch` and `localStorage` (blocked storage included), and a scan of `index.html`, `app.js`, `atom.js` and `style.css` for forbidden things (HTML injection, `eval`, inline script or handlers, absolute addresses, service worker, Cache API, other storage).
- `site/tests/logic.test.mjs`: `node --test` for `logic.js`. It runs every case of the four sections of `tests/shared-cases.json` (cleaning, time, keywords for every topic, topics) against `logic.js`, so Python and JavaScript cannot drift apart (R4.5), plus JavaScript-only tests for the URL check, `id`, summer time transitions, selection, merge and sort.
- `requirements.txt`, `pytest.ini`, `.gitignore` (lists `build/`, the output of the build).

## Run the build locally
Needs Python 3.10 or newer and no packages (standard library only). From this folder:

```
python -m newsreader --out build
python -m http.server 8000 --directory build
```

Then open `http://localhost:8000/` in a browser. The first command prints one line per build source (`svt: ok, 31 items`) and one indented line per feed (`  politics: ok, 11 items`) and writes the folder `build/`, which is listed in `.gitignore` and never committed. Run it again whenever you want fresh headlines, and press "Uppdatera" on the page (or wait up to 10 minutes) to load them.

The page must be opened through the local server. Opening `build/index.html` directly from the disk (`file://`) does not work: the browser does not let the page read `news.json` and `sources.json` from a `file://` address, so the page then only says "Kunde inte hämta nyheter. Försök igen senare." (This is by design: the design only describes the local server, R12.1.) The saved copy of the last list (local storage, per address, so use the same address and port every time) is shown, with a notice, when `news.json` cannot be loaded but `sources.json` can; if `sources.json` cannot be loaded either, the page cannot check the links and shows the failure text.

What the command does:
- Reads and checks `sources.json` (version 2) and loads every keyword file that its `topics` name (`politics-keywords.json`, `nature-keywords.json`, `ai-keywords.json`): each must exist next to `sources.json`, belong to its topic and be valid (R14.5, R17.5). If `sources.json` is invalid (a version 1 file included) or a keyword file is missing or invalid (the message names the file), the command prints a message on stderr, exits with code 1 and writes nothing. Nothing else makes the build fail: a source or a feed that cannot be fetched never does (R6.4).
- For each source that is enabled and has `fetchedBy: build` (today only SVT): collects the distinct feed addresses of all its feed entries (`BUILD_TOPICS`: all four topics since F5, so SVT costs two feed requests, `nyheter/rss.xml` once for Alla nyheter, Natur and AI and `nyheter/inrikes/rss.xml` once for Politik), reads the host's `/robots.txt` once per run and host (not counted as a feed request), and does not fetch a path that is disallowed for the user agent `GithubAutoPlay-news-reader/1.0` (status `blocked-by-robots`). A `robots.txt` that answers 404 or another 4xx except 429 means no rules, so the feed is fetched. A group in `robots.txt` names us by `GithubAutoPlay-news-reader` or by the full agent line with `/1.0` (case does not matter), a leading byte order mark is ignored, and percent-encoded unreserved characters (`%7E` and `~`) are treated as the same, as are raw non-ASCII characters and their UTF-8 percent-encoding (`/ä` and `/%C3%A4`). One that cannot be read (timeout, network error, 5xx, 429, over 2 MiB, not UTF-8 text, redirect to another host) means the source is not fetched and gets the status `error`, so the 24-hour fallback below applies. Then it makes one request for each address, with that User-Agent, no cookies, a timeout of 15 seconds, redirects only to https addresses on the source's `allowedHosts`, and a limit of 2 MiB that is enforced while the body is downloaded, and a total limit of 60 seconds for the whole download (checked after every piece of data that arrives, so a server that sends one byte at a time cannot keep the build waiting). Every failure inside the fetch layer (invalid address, broken connection, incomplete body) is a `FetchError`, so it is a failed feed and never a crash. Sources with `enabled: false` are not fetched and not listed. Sources with `fetchedBy: browser` (Sveriges Radio) are never fetched, never listed and never stored: the build refuses to run if such a source reaches the fetch step by mistake, and `sources.json` is invalid if a browser source does not have `storageAllowed: false`.
- Evaluates each feed entry on the parsed response of its address (R13.3): method `feed` gives every item the topic, method `keywordFilter` gives it when the keyword list of the topic matches the headline and description (`topics_of`; with `matchOn` `title` only the headline). Per item: an empty headline, an unusable link (R9.1) or no topic drops it; the same article (same normalised URL) from several addresses, or twice in one feed, is one item with the union of its topics, taking headline, link and time from the first occurrence that is not older than 7 days (addresses in the order of `sources.json`, then feed order; a copy older than 7 days does not count, so a fresher copy of the same article from another feed still gives the item). Then the cap is applied per source and topic (R13.6): the 20 newest items of each topic are kept, the `topics` of an item list only the topics it was kept in, and an item left with no topic is dropped. So `news.json` holds at most 20 items per source and topic, SVT's up to 80 distinct items.
- Writes `build/news.json` (UTF-8, version 2): `generatedAt`, `generatedAtDisplay`, `topics` (the topic ids of `sources.json`), `sources` and `items`. Each item has eight fields: `id`, `sourceId`, `sourceName`, `title`, `url`, `published`, `publishedDisplay` and `topics` (ids in the order of `sources.json`, no duplicates). Each source has `id`, `name`, `status` (the worst of its feeds: `error`, then `blocked-by-robots`, then `ok`), `lastSuccess` (the oldest of its feeds, `null` if one never succeeded), `itemCount` (distinct items of the source), a `message` when the status is not `ok` (the message of the first feed in `sources.json` order that has that status) and `feeds`: one entry per feed entry of `sources.json` with `topic`, `status`, `lastSuccess`, `itemCount` (items that have the topic) and a `message` when not `ok`. Feed entries that share an address share status, `lastSuccess` and message. The message is fixed text or the name of an exception class, never feed content, and no address is written to `news.json`. The build checks its own output against this shape before writing (R19.6) and refuses to write otherwise. Then it copies the content of `site/` (without its `tests` folder; symbolic links inside `site/` are skipped, not followed), `sources.json` and every keyword file named in it into `build/`. The page files are therefore at the top of `build/`, next to `news.json`.
- A feed address that fails (network error, status other than 200, redirect to another host, response over 2 MiB, not RSS 2.0, a feed with no items, a robots.txt that cannot be read, or a selection error such as the not yet supported `categoryFilter` method) marks every feed entry that uses it with the status `error` and a message, and the build goes on with the other addresses (a failure is per address; the source's other feeds are fetched and shown as usual). A blocked address (robots.txt) marks its feed entries `blocked-by-robots`. Fallback, per feed entry: if the previous `news.json` has a `lastSuccess` for the feed that is less than 24 hours old, the items of that source that have the topic of the feed are kept (valid ones only, and not older than 7 days, R5.2); they get back only the topics of the failed feeds, joined with the topics from feeds that worked, and the cap is applied again. After 24 hours nothing is kept and `lastSuccess` keeps the time of the last real success. A feed that is fetched fine but has no matching item is `ok` with `itemCount` 0. Items of a blocked feed are not kept. A previous file of version 1 (made before F5) is read as follows: all its items have the topic `politics`, and the feed `politics` has the source's `lastSuccess`; other feeds have no previous items. A previous file of another version is ignored.
- The previous file is `build/news.json` if it exists (read before it is overwritten, so the fallback works locally), or the file named by `--previous <file>`. A missing or unreadable previous file means no fallback.
- The output folder may not be the project folder, `site/` or a folder inside it, or a folder that holds the project (compared by the real path, so spelling, case and links do not help), and it may not be a symbolic link (a symbolic link `site/` is followed for this check, and a new folder inside `site/` is refused too). The build also refuses to write when `news.json`, `news.json.tmp` or any copied file (or a folder on the way) in the output folder is a symbolic link: nothing is written through links and nothing is written at all in that case. Every file is written to a temporary file next to its target and renamed over it, so a hard link to an old file keeps its old content. Running the build twice gives the same files. Files that were once copied from `site/` and later removed there stay in `build/` until you delete the folder.

The tests cover all of this with a fake fetch layer. They never fetch a real site, so **a check against the real SVT feed is done by the owner or manager** (see step S8 of the design): run the command above on a machine with internet access, look at the status line for `svt` and at `build/news.json`, and judge how well the keyword list selects politics (K6). That check also confirms the real robots.txt answer, the host of the item links (Q2) and that the 15-second timeout and 2 MiB limit are enough for the real feed.

Check by hand against the real SVT feeds (F5, the owner or manager; the tests cannot do this): after `python -m newsreader --out build`,
- the output has the line `svt: ok, N items` and four feed lines (`all-news`, `politics`, `nature`, `ai`), all `ok`; the build made exactly two feed requests (`nyheter/rss.xml` and `nyheter/inrikes/rss.xml`) and one `robots.txt` request (watch the network, or run it twice within a few minutes and note that nothing else is requested);
- `build/news.json` has `"version": 2`, `topics`, and for `svt` a `feeds` list with one entry per topic and no address in it; items have eight fields; no item has a description or an image; no Sveriges Radio item is in the file;
- read the lists per topic (items whose `topics` contain `all-news`, `politics`, `nature`, `ai`): at most 20 each; look for false positives and misses of the Natur and AI lists on the live feed (K15, K16); an article about several things has several topics;
- the item links of Alla nyheter are on `www.svt.se` (Q2) and the headlines look right (Swedish letters);
- the page at `http://localhost:8000/` shows the same politics list as before (SVT politics and Sveriges Radio) and nothing from the other topics; the "Källor" row of SVT says "Hämtad, N rubriker" with N the politics headlines shown (R19.8, until F7);
- stop the network for one address (or edit `build/news.json` so that `lastSuccess` is an hour old and block `nyheter/inrikes/rss.xml`) and build again: that feed gets `error` with its old items kept, the other feeds stay current.

## Checks by hand (the Sveriges Radio live fetch)
The tests use a fake `fetch` and a stand-in XML parser, so these checks need a real browser (run the build and `python -m http.server 8000 --directory build`, open `http://localhost:8000/`):
- Storage: in the developer tools, Application tab, look at Local storage, Session storage, IndexedDB, Cache storage, Service workers and Cookies for the page. Only `newsReader.selectedSources` and `newsReader.lastNews` may exist, and `newsReader.lastNews` must hold no Sveriges Radio headline or link.
- Console: open the Console, reload and press "Uppdatera". No lines from the page. (The browser itself may print a line if a request is blocked, naming the address only. If the feed is not well-formed XML, Chromium also reports that its own error page for `DOMParser` breaks the style rule of the page's Content-Security-Policy; the line names style hashes only and holds nothing from the feed.)
- Call count: in the Network tab, filter on `api.sr.se`. One request when the page opens. "Uppdatera" within 5 minutes adds none. Leave the tab hidden for 15 minutes: none while it is hidden; one when you come back.
- Unticked: untick Sveriges Radio in "Källor", reload, press "Uppdatera" and wait for the timer. Zero requests to `api.sr.se` while it is unticked; tick it and one request follows (if none was made in the last 5 minutes). The `Referer` header of the request is absent.
- Blocking: block `api.sr.se` (Network tab, "Block request URL", or turn the network off for it). SVT items stay, "Källor" says "Sveriges Radio kunde inte hämtas just nu", and no retry follows before the next allowed time.
- The source name "Sveriges Radio" is on every Sveriges Radio item, and the Atom feed is read by the real `DOMParser` (items appear).
