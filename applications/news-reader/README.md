# News reader

A web page that lists headlines about politics in Sweden from a few owner-approved sites (today SVT and Sveriges Radio). Each item shows the headline, the source, the publication time and a link to the original article. The page text and the news are in Swedish.

Status: skeleton (S2) plus the RSS parser headline cleaning of the build (S4) and time handling (S5). Keywords, selection, fetching and the page come in later steps. See the [design](news-reader-design.md) for the goal, requirements, architecture and step plan.

## Files
- `sources.json`: the approved sources. SVT is collected by the build (`fetchedBy: build`, may be stored). Sveriges Radio is fetched live in the browser (`fetchedBy: browser`) and must never be stored (`storageAllowed: false`). Changes only through issues approved by the owner.
- `newsreader/`: the Python build, standard library only. So far: `model.py` (`RawEntry`: title, link, time text, description), `parse.py` (`parse_rss`: RSS 2.0 bytes to raw entries) and `select.py` (`clean_headline`, R1.3) and `timeutil.py` (time handling, R2, see below). `parse_rss` decodes by the XML declaration (UTF-8, ISO-8859-1), refuses a response over 2 MB, refuses documents that declare any entity (the XML parser itself rejects the declaration, so no external entities are resolved), and accepts only UTF-8 and ISO-8859-1 (UTF-16, UTF-32 and any other declared encoding are refused), and raises `FeedError` for empty, malformed or non-RSS documents (the root must be `<rss>`). Items with no title, link, time and description are skipped; other items are kept raw, with an empty string for a missing field. Dropping items with an empty headline or an unusable link is done later by the selection step.
- `tests/shared-cases.json`: cases shared by the Python and JavaScript tests, with the sections `cleaning` and `time` (filled) and `keywords` (empty for now). Each case has `id`, `input` and `expected`; a `time` case has `input` `{text, now}` (the feed's time text or `null`, and the "now" of the build as UTC text) and `expected` `{published, publishedDisplay}`. Headline cleaning is defined with fixed sets so that the JavaScript version (S9) can reproduce it exactly and does not depend on any library table:
  - Tags: `<` followed by a letter or `/` up to `>`, and `<!-- ... -->` comments, are removed (`a < b` is not a tag).
  - Entities are decoded once, in one pass: `&amp; &lt; &gt; &quot; &apos;`, numeric references (decimal and hex, any number of digits) for code points from 1 to U+10FFFF except surrogates (U+D800 to U+DFFF), and the named list `&nbsp; &laquo; &raquo; &ndash; &mdash; &hellip; &lsquo; &rsquo; &ldquo; &rdquo; &auml; &ouml; &aring; &Auml; &Ouml; &Aring; &eacute; &Eacute; &euro; &copy;` (case-sensitive). Everything else is left exactly as written: entities without a semicolon, other names, `&#0;`, surrogates, values above U+10FFFF. `&#128;` is the plain control character U+0080, not the euro sign.
  - White space is exactly U+0020, tab, LF, CR, FF, VT and U+00A0 (no-break space): runs become one space and leading and trailing ones are removed. The JavaScript version must use this explicit set, not `trim()` or `\s`. Other Unicode spaces are kept.
- Time handling (`newsreader/timeutil.py`, R2): `published_utc(text, now)` turns the feed's time text into `YYYY-MM-DDTHH:MM:SSZ` or `None`; `display_time(published)` gives `YYYY-MM-DD HH:MM` in Europe/Stockholm, or `Tid saknas` for `None`; `generated_at(now)` and `generated_at_display(now)` give the two fields of R2.7. `now` is always passed in (an aware datetime), never read from the clock. Rules, written out so that S9 can copy them:
  - Accepted: RFC 822/2822 (`Fri, 13 Nov 2026 14:05:00 +0100`; the weekday is optional and not checked; seconds optional; the zone is `+HHMM`, `-HHMM` or one of `UT UTC GMT Z EST EDT CST CDT MST MDT PST PDT`) and ISO 8601 `YYYY-MM-DDTHH:MM[:SS]` with `Z` or an offset `+HH:MM`, `+HHMM` or `+HH` (a fraction of a second is ignored, not rounded). Digits are ASCII only. Leading and trailing white space is ignored. Any other text, other zone names (for example `CET`), a date without a time, or an impossible date or time (32 November, 29 February in a non-leap year, hour 24, minute 60, second 60) gives `null`.
  - No zone: read as Europe/Stockholm wall-clock time. The two hours around the switches are resolved like this: a local time that does not exist (02:00 to 02:59 on the last Sunday of March) uses the winter offset +01:00, so `02:30` is `01:30Z` and is shown as `03:30`; a local time that exists twice (02:00 to 02:59 on the last Sunday of October) is read as the first occurrence, the summer offset +02:00, so `02:30` is `00:30Z` and is shown as `02:30`. UTC instants are shown exactly (`2026-10-25T01:30:00Z` is the second `02:30`).
  - A time more than 10 minutes after `now` is `null` (exactly 10 minutes is kept). `published` is always whole seconds in UTC.
  - Note for S9: the JavaScript version must give the same text. `Intl.DateTimeFormat("sv-SE", {timeZone: "Europe/Stockholm", hourCycle: "h23", ...})` can supply the parts (year, month, day, hour, minute), which are then joined by hand into `YYYY-MM-DD HH:MM` (do not rely on the locale's own separators; `hour12: false` can give `24:00` in some engines, so use `hourCycle: "h23"`). For a time without zone, Intl cannot parse local time, so use an explicit rule: guess the UTC instant from the fields, find the Stockholm offset (+1 or +2 hours; summer time runs from 01:00 UTC on the last Sunday of March to 01:00 UTC on the last Sunday of October), and apply the gap and repeated-hour rules above. Use the same ASCII-digit regular expressions as `timeutil.py` and build dates with `Date.UTC` plus an explicit range check (`Date` accepts 32 November and rolls it over). All shared `time` cases must pass.
  - `zoneinfo` needs a time zone database. On Linux, macOS and the `ubuntu-latest` runner of `ci.yml` the system database is used. A machine without one (typically Windows without the `tzdata` package) fails with `ZoneInfoNotFoundError`; if that happens run `python -m pip install tzdata`. `tzdata` is not in `requirements.txt` because CI does not need it.
- `tests/fixtures/`: hand-written, invented sample feeds (`rss_svt_shape.xml` is invented, in the shape of an SVT feed) for the parser tests (no real feed content).
- `tests/test_parse.py`, `tests/test_cleaning.py`, `tests/test_time.py`: tests of the parser, of the cleaning and of the time handling, the latter two driven by the shared cases plus direct tests.
- `tests/test_sources.py`: validates `sources.json` against the rules in the design.
- `site/logic.js`: placeholder for the page logic, with a Node smoke test in `site/tests/`.
- `requirements.txt`, `pytest.ini`, `.gitignore` (lists `build/`, the output of the build).

## Run the tests locally
Needs Python 3.10 or newer and Node.js 18 or newer. From this folder (`node --test` finds the `*.test.mjs` files by itself; passing a folder name does not work on Node 22):

```
python -m pip install -r requirements.txt
python -m pytest
node --test
```

From the repository root, `bash scripts/check.sh applications/news-reader` runs the Python tests together with the other checks. The tests need no network.
