# News reader

A web page that lists headlines about politics in Sweden from a few owner-approved sites (today SVT and Sveriges Radio). Each item shows the headline, the source, the publication time and a link to the original article. The page text and the news are in Swedish.

Status: skeleton (S2) plus the RSS parser and headline cleaning of the build (S4), time handling (S5), the shared keyword list with keyword matching (S6), item selection with the final item shape (S7) and the build command with `news.json` (S8). The JavaScript twin of the build logic, `site/logic.js`, is done (S9). The page, part 1 (S10: SVT headlines, the choice of sources, offline copy, notices) is done; the Sveriges Radio live fetch is step S11. See the [design](news-reader-design.md) for the goal, requirements, architecture and step plan.

## Files
- `sources.json`: the approved sources. SVT is collected by the build (`fetchedBy: build`, may be stored). Sveriges Radio is fetched live in the browser (`fetchedBy: browser`) and must never be stored (`storageAllowed: false`). Changes only through issues approved by the owner.
- `politics-keywords.json`: the one shared keyword list that decides which items are about Swedish politics (R4.3). The Python build reads it, and the page will fetch the same file (S9), so there is no second copy of the terms. Shape (design section 7.2): `version` (1), `category` (`politics-sweden`), `include.words` (single words, written lower case in the file; capitals as in design 7.2 are also accepted and lowercased by the loader, a trailing `*` makes a prefix term), `include.caseSensitive` (exact substrings such as `(SD)`, case kept), `exclude.words` (words that never count, for example `moderat`) and `exclude.phrases` (phrases of two or more words, for example `tyska regeringen`, removed before matching). `minister`, `val` and `parti` are not include terms on purpose (too broad). Changes only through issues, when false positives or negatives are found (K6).
- `newsreader/`: the Python build, standard library only. So far: `model.py` (`RawEntry`: title, link, time text, description), `parse.py` (`parse_rss`: RSS 2.0 bytes to raw entries) and `select.py` (`clean_headline`, R1.3, and the item selection, see below) and `timeutil.py` (time handling, R2, see below) and `keywords.py` (keyword list and matching, R4.4, see below). `parse_rss` decodes by the XML declaration (UTF-8, ISO-8859-1), refuses a response over 2 MB, refuses documents that declare any entity (the XML parser itself rejects the declaration, so no external entities are resolved), and accepts only UTF-8 and ISO-8859-1 (UTF-16, UTF-32 and any other declared encoding are refused), and raises `FeedError` for empty, malformed or non-RSS documents (the root must be `<rss>`). Items with no title, link, time and description are skipped; other items are kept raw, with an empty string for a missing field. Dropping items with an empty headline or an unusable link is done later by the selection step.
- `tests/shared-cases.json`: cases shared by the Python and JavaScript tests, with the sections `cleaning`, `time` and `keywords` (all filled). Each case has `id`, `input` and `expected`; a `keywords` case has `input` `{headline, description}` (`description` may be missing, `null` or empty) and `expected` `{match}` (true or false); a `time` case has `input` `{text, now}` (the feed's time text or `null`, and the "now" of the build as UTC text) and `expected` `{published, publishedDisplay}`. Headline cleaning is defined with fixed sets so that the JavaScript version (S9) can reproduce it exactly and does not depend on any library table:
  - Tags: `<` followed by a letter or `/` up to `>`, and `<!-- ... -->` comments, are removed (`a < b` is not a tag).
  - Entities are decoded once, in one pass: `&amp; &lt; &gt; &quot; &apos;`, numeric references (decimal and hex, any number of digits) for code points from 1 to U+10FFFF except surrogates (U+D800 to U+DFFF), and the named list `&nbsp; &laquo; &raquo; &ndash; &mdash; &hellip; &lsquo; &rsquo; &ldquo; &rdquo; &auml; &ouml; &aring; &Auml; &Ouml; &Aring; &eacute; &Eacute; &euro; &copy;` (case-sensitive). Everything else is left exactly as written: entities without a semicolon, other names, `&#0;`, surrogates, values above U+10FFFF. `&#128;` is the plain control character U+0080, not the euro sign.
  - White space is exactly U+0020, tab, LF, CR, FF, VT and U+00A0 (no-break space): runs become one space and leading and trailing ones are removed. The JavaScript version must use this explicit set, not `trim()` or `\s`. Other Unicode spaces are kept.
- Time handling (`newsreader/timeutil.py`, R2): `published_utc(text, now)` turns the feed's time text into `YYYY-MM-DDTHH:MM:SSZ` or `None`; `display_time(published)` gives `YYYY-MM-DD HH:MM` in Europe/Stockholm, or `Tid saknas` for `None`; `generated_at(now)` and `generated_at_display(now)` give the two fields of R2.7. `now` is always passed in (an aware datetime), never read from the clock. Rules, written out so that S9 can copy them:
  - Accepted: RFC 822/2822 (`Fri, 13 Nov 2026 14:05:00 +0100`; the weekday is optional and not checked; seconds optional; the zone is `+HHMM`, `-HHMM` or one of `UT UTC GMT Z EST EDT CST CDT MST MDT PST PDT`) and ISO 8601 `YYYY-MM-DDTHH:MM[:SS]` with `Z` or an offset `+HH:MM`, `+HHMM` or `+HH` (a fraction of a second is ignored, not rounded). Digits are ASCII only. An ISO time with a space instead of `T` (`2026-11-13 12:00:00`) gives `null`. The year must be 1970 to 9998 (checked on the parsed fields before any conversion); any other year gives `null`, so no input can overflow `datetime`. Leading and trailing white space is ignored. Any other text, other zone names (for example `CET`), a date without a time, or an impossible date or time (32 November, 29 February in a non-leap year, hour 24, minute 60, second 60) gives `null`.
  - No zone: read as Europe/Stockholm wall-clock time. The two hours around the switches are resolved like this: a local time that does not exist (02:00 to 02:59 on the last Sunday of March) uses the winter offset +01:00, so `02:30` is `01:30Z` and is shown as `03:30`; a local time that exists twice (02:00 to 02:59 on the last Sunday of October) is read as the first occurrence, the summer offset +02:00, so `02:30` is `00:30Z` and is shown as `02:30`. UTC instants are shown exactly (`2026-10-25T01:30:00Z` is the second `02:30`).
  - A time more than 10 minutes after `now` is `null` (exactly 10 minutes is kept). `published` is always whole seconds in UTC.
  - Note for S9 (done: `site/logic.js` does not use `Intl` at all, it writes the Stockholm rules out as described under `site/logic.js` below; the note is kept as the original reasoning): the JavaScript version must give the same text. `Intl.DateTimeFormat("sv-SE", {timeZone: "Europe/Stockholm", hourCycle: "h23", ...})` can supply the parts (year, month, day, hour, minute), which are then joined by hand into `YYYY-MM-DD HH:MM` (do not rely on the locale's own separators; `hour12: false` can give `24:00` in some engines, so use `hourCycle: "h23"`). For a time without zone, Intl cannot parse local time, so use an explicit rule: guess the UTC instant from the fields, find the Stockholm offset (+1 or +2 hours; summer time runs from 01:00 UTC on the last Sunday of March to 01:00 UTC on the last Sunday of October), and apply the gap and repeated-hour rules above. Use the same ASCII-digit regular expressions as `timeutil.py` (Python's `\Z` is JavaScript's `$` without the `m` flag), and never format with a library that does not zero-pad years (`timeutil.py` pads every field by hand). `Date.UTC` reads the years 0 to 99 as 1900 to 1999, which is a non-issue because the year range rule rejects those years first and build dates with `Date.UTC` plus an explicit range check (`Date` accepts 32 November and rolls it over). All shared `time` cases must pass.
  - `zoneinfo` needs a time zone database. On Linux, macOS and the `ubuntu-latest` runner of `ci.yml` the system database is used. A machine without one (typically Windows without the `tzdata` package) fails with `ZoneInfoNotFoundError`; if that happens run `python -m pip install tzdata`. `tzdata` is not in `requirements.txt` because CI does not need it.
- Keyword matching (`newsreader/keywords.py`, R4.4): `load_keywords()` reads and validates `politics-keywords.json` and returns a `Keywords` object; `.matches(headline, description=None)` gives true or false. `KeywordsError` (a `ValueError`) is raised for an invalid file, so the build (S8) fails as R6.4 says: wrong or extra keys, wrong version or category, a term that is empty, has surrounding white space, or is duplicated (the error names the term; duplicate JSON keys are named too), a `caseSensitive` term that is not NFC, a `words` term that is not one word, a wildcard anywhere but at the end, an exclude phrase that is not two or more words separated by single spaces. The description is only read for matching and is never returned or stored. Rules, written out so that S9 can copy them exactly:
  - Term normalisation: terms in `include.words`, `exclude.words` and `exclude.phrases` may be written with capitals; the loader makes them NFC and then lower case, and finds duplicates after that (`Riksdag*` next to `riksdag*` is an error). `include.caseSensitive` terms are kept exactly as written. The S9 loader must do the same: `normalize("NFC")`, then `toLowerCase()`, duplicates checked after lowercasing.
  - Headline and description are each cleaned with `clean_headline` first and tested separately; a hit in either is a match. A missing, `null` or empty description is ignored.
  - The cleaned text is NFC-normalised and split into words: maximal runs of Unicode letters (category starting with L) and decimal digits (Nd). So `-`, `_`, `/`, spaces and punctuation split words, while å, ä, ö and any other letter or digit next to a term make it a different word. Each word is lowercased.
  - An `include.words` term matches a whole word; a term ending in `*` matches every word that starts with the term without the `*` (`riksdag*` matches `riksdagsledamot`, but not `vårdriksdagen`; `rosenbad` does not match `rosenbadet`).
  - `exclude.phrases`: every place where a phrase's words follow each other is marked, and the marked words are taken out together before matching (so a headline with `tyska regeringen` and `riksdagen` still matches, and overlapping or adjacent phrases behave the same everywhere). A phrase never spans the headline and the description.
  - `exclude.words`: a word equal to one of them never counts as a hit (`moderat` and `moderata`; `Moderaterna` and `moderatledaren` still match). The official name "Moderata samlingspartiet" is therefore not matched, as the design accepts.
  - `include.caseSensitive` terms are exact substrings of the NFC-normalised cleaned text, case and brackets kept (`(SD)` matches, `(sd)` and `[SD]` do not). Exclude phrases and words do not affect them. The other terms are lowercased when the file is loaded, so only these keep their capitals.
  - Exclusion never drops a whole item; it only takes words and phrases out of consideration.
  - Note for S9: use `[\p{L}\p{Nd}]+` with the `u` flag for the words (not `\w`, `isalpha`-like tests or `\b`), `String.prototype.normalize("NFC")` before splitting, `toLowerCase` on each word, plain `includes` for the case-sensitive terms and a word-by-word comparison for the phrases (no regular expression built from the terms). Python and JavaScript may differ for characters added in newer Unicode versions; the shared `keywords` cases must pass in both. Validate the file in the page the same way (or at least in the build, which fails on an invalid file).
- Known limits (K6): the list is approximate. Accepted for now and handled by follow-up issues:
  - False negatives: possessive party names (`Centerpartiets`), abbreviations without brackets (`M-ledaren`, `SD kräver`), headlines that name only a person or a minister, and `Valet 2026` (`val` is not an include term).
  - False positives: foreign governments outside the phrase list (`Spanska regeringen`, `Norges regering`, `USA:s regering`) and brackets used for other things (`Storlek (L)`).
- Item selection (`newsreader/select.py`, R1.1, R1.4, R5.1 to R5.4, R9.1): `select_items(entries, source, keywords, now)` turns the raw entries of one source (`source` is its entry in `sources.json`, `now` an aware datetime, never read from the clock) into a list of `NewsItem` (`model.py`), which has exactly the seven fields of R1.1 (`id`, `sourceId`, `sourceName`, `title`, `url`, `published`, `publishedDisplay`; `as_dict()` gives the form for `news.json`). The description is used for the keyword filter only and is dropped. A source is filtered by keywords when `politics-sweden.method` in `sources.json` is `keywordFilter` (a `feed` source is not filtered; `categoryFilter` raises `ValueError` until raw entries carry categories). Disabled sources and browser sources are not handled here (S8). Rules, written out so that S9 can copy them:
  - Order of the steps: clean the headline (empty drops the item), keyword filter, URL check, de-duplicate, age limit, sort, cap of 20.
  - URL check (`parse_url`, `check_url`): white space around the text is ignored; the rest may only hold the printable ASCII characters U+0021 to U+007E (so no inner white space, control characters, raw IDN or other non-ASCII; punycode `xn--` is plain ASCII) and no backslash. The scheme is `http` or `https` (any case). The authority may not hold `@` (`https://svt.se@evil.com/`), a port (even the default one) or a trailing dot, and the host must be lower-cased dot-separated labels of `a-z 0-9 -`. The host must equal an `allowedHosts` entry or end with `.` plus one (`www.svt.se` yes, `evilsvt.se` no). No `urllib` is used, because its leniency differs between languages. The item keeps its URL as in the feed (trimmed).
  - Normalised URL (R5.3, used for duplicates and the `id`): lower-case scheme and host, one leading `www.` removed from the host, query and fragment removed, all trailing `/` removed (`https://svt.se/` is `https://svt.se`). The path keeps its case and is not percent-decoded; `http` and `https` stay different. Duplicates are found per source after the other drops, and the first one in feed order is kept.
  - `id` (R5.4): the first 16 hex characters (lower case) of the SHA-256 of the normalised URL as UTF-8.
  - Age (R5.2): `published` older than 7 days before `now` is dropped, exactly 7 days is kept. An item without time (or with a bad or future time, which gives `null`) is kept.
  - Order and cap (R5.1, R5.5): newest `published` first, items with `null` last; equal times by title compared by Unicode code point (JavaScript must compare code points, not UTF-16 units), then feed order; the first 20 are kept, so undated items only fill the free places.
  - The shared cases file has no `selection` section: design section 9 keeps the three sections `cleaning`, `time` and `keywords` there, and the JavaScript side tests selection with its own plain-object tests in S9. The URL lists in `tests/test_selection.py` (`GOOD_URLS`, `BAD_URLS`) are meant to be reused as the S9 test data.
- Build command (S8): `newsreader/__main__.py` (the command line), `build.py` (orchestration and output), `fetch.py` (the only network module) and `robots.py` (robots.txt decision). See "Run the build locally" below.
- `tests/fixtures/`: hand-written, invented sample feeds (`rss_svt_shape.xml` is invented, in the shape of an SVT feed) for the parser tests (no real feed content).
- `tests/test_selection.py`: tests of the URL check and normalisation, the `id`, the item shape, the drops, duplicates, age limit, sorting and cap, with hand-written data.
- `tests/test_parse.py`, `tests/test_cleaning.py`, `tests/test_time.py`, `tests/test_keywords.py`: tests of the parser, of the cleaning, of the time handling and of the keyword list and matching (validation of `politics-keywords.json` with invalid variants, plus the shared cases), driven by the shared cases plus direct tests.
- `tests/test_build.py`, `tests/test_fetch.py`, `tests/test_robots.py`: tests of the build, the fetch layer and the robots.txt rule. They use a fake fetch layer (`tests/fakes.py`), invented headlines and invented `example.invalid` hosts, so they need no network and contain no real feed content.
- `tests/test_sources.py`: validates `sources.json` against the rules in the design.
- `site/logic.js` (S9): the pure logic of the page, the JavaScript twin of `select.py`, `keywords.py` and `timeutil.py`. No DOM, no network, no storage, no clock (`now` is always a parameter: a `Date`, epoch milliseconds, or UTC text like `2026-11-13T13:05:12Z`), no dependencies. It is a classic script that also works under Node (not an ES module: a page loads it with `<script src="logic.js">` and uses the global `NewsLogic`; Node uses `require` or `import logic from "./logic.js"`; do not add `"type": "module"` to a `package.json` above it). Functions:
  - `cleanHeadline(text)`: tags removed, the fixed entity set decoded once, the white space set ` \t\n\r\f\v` and U+00A0 (not `trim()` or `\s`).
  - `validateKeywords(parsedJson)` (same checks and normalisation as `load_keywords`; the page fetches `politics-keywords.json`, parses it and passes it in; a duplicate JSON key cannot be seen after `JSON.parse`, the Python side rejects it) and `matchesKeywords(keywords, headline, description)`.
  - `checkUrl(url, allowedHosts)` (normalised URL or `null`; same rules as `check_url`), `parseUrl`, `itemId(normalisedUrl)` and `sha256Hex(text)` (a small synchronous pure-JS SHA-256, so it works in Node and browsers without `crypto.subtle`).
  - Time: `publishedUtc(text, now)`, `displayTime(published)`, `parseTime`, `formatUtc`, `generatedAt(now)`, `generatedAtDisplay(now)`. Europe/Stockholm is written out, not read from `Intl`, so Node and every browser give the same text: no summer time in 1970-1979; in 1980 from 6 April; from 1981 from the last Sunday of March; ends the last Sunday of September until 1995 and of October from 1996; changes at 01:00 UTC; years 1970 to 9998 as in Python. A local time in the skipped hour is read as +01:00, a repeated hour as the first occurrence (+02:00). These are the rules Python's `zoneinfo` gives (checked for every year 1970 to 9998). `displayTime` throws `Error` for text that is not a UTC time, like Python's `ValueError`.
  - Where JavaScript is not identical to Python (known and accepted): `displayTime` shows times before 1970 with +01:00 (Python uses local mean time before 1893 and so on), which parsed input can never reach (a parsed time is at most one day before 1970). Node and Python can ship different Unicode data versions, so for very new characters the word class (`\p{L}`, `\p{Nd}`), NFC and lower-casing can differ. `validateKeywords` cannot tell `1.0` from `1` in `version` because `JSON.parse` gives the same number. A selected item whose time is before the 7 day limit is dropped, also when the time is before 1970 (Python's `select_items` does not handle that case). An Atom `published` that is only white space falls back to `updated`. All text trimming is done with linear scans, so very long inputs are handled quickly.
  - `selectItems(entries, source, keywords, now)`: the steps of `select_items`, returning items with exactly the seven fields of R1.1. An entry is a plain object: `title`, `link`, the time as `timeText` (Python shape) or `published` falling back to `updated` (Atom, used when `published` is missing or empty), the description as `description` or `summary`; `content` is never read.
  - `mergeItems(listsOfItems)` merges the items of several sources and sorts them (R5.5): `published` newest first, `null` last, equal times by `sourceId`, then `title` (compared by Unicode code point), then the order given; nothing is de-duplicated across sources. `sortItems(items, bySource)` is the sort alone.
- `site/index.html`, `site/app.js`, `site/style.css` (S10): the page. `index.html` is the Swedish skeleton (`lang="sv"`, `noindex`, a Content-Security-Policy meta tag that only allows the page's own scripts, styles and requests, no inline script or style). `app.js` is a thin classic script that loads `sources.json` and `news.json` from its own folder, validates them (types, sizes, links through `NewsLogic.checkUrl`, time text recomputed by `NewsLogic`), merges and sorts with `NewsLogic.mergeItems` and writes the DOM with `createElement` and `textContent` only. It shows headline, source name, time and link for each item (links open in a new tab with `rel="noopener noreferrer"`), the section "Källor" (a labelled check box per enabled source with the note "Urval med nyckelord – ungefärligt" and the source's status), the notices (offline copy, stale data, empty choice, failed load) and the bottom line with the source names from `sources.json`. Loading: when the page opens, every 10 minutes while the tab is visible, and on "Uppdatera"; a failed load keeps what is shown. localStorage: `newsReader.selectedSources` (the chosen source ids; all sources on the first visit, and when storage is blocked) and `newsReader.lastNews` (the last good `news.json`, SVT only, validated again when read). Every storage access is in try/catch and the page works without it. No service worker, no Cache API, no requests to other sites. The Sveriges Radio row in "Källor" has its check box and says "Inte tillgänglig ännu" until step S11 (`browserStatus` in `app.js` is the only function S11 replaces for that text). `app.js` also works under Node (`require`), exporting its pure parts for the tests.
- `site/tests/app.test.mjs`: `node --test` for `app.js`: validation of `sources.json`, `news.json`, the saved copy and the saved choice, the notices and the rows of "Källor", the whole page against a small hand-written fake DOM and fake `fetch` and `localStorage` (blocked storage included), and a scan of `index.html`, `app.js` and `style.css` for forbidden things (HTML injection, `eval`, inline script or handlers, absolute addresses, service worker, Cache API, other storage).
- `site/tests/logic.test.mjs`: `node --test` for `logic.js`. It runs every case of the three sections of `tests/shared-cases.json` (cleaning, time, keywords) against `logic.js`, so Python and JavaScript cannot drift apart (R4.5), plus JavaScript-only tests for the URL check, `id`, summer time transitions, selection, merge and sort.
- `requirements.txt`, `pytest.ini`, `.gitignore` (lists `build/`, the output of the build).

## Run the build locally
Needs Python 3.10 or newer and no packages (standard library only). From this folder:

```
python -m newsreader --out build
python -m http.server 8000 --directory build
```

Then open `http://localhost:8000/` in a browser. The first command prints one line per build source (`svt: ok, 11 items`) and writes the folder `build/`, which is listed in `.gitignore` and never committed. Run it again whenever you want fresh headlines, and press "Uppdatera" on the page (or wait up to 10 minutes) to load them.

The page must be opened through the local server. Opening `build/index.html` directly from the disk (`file://`) does not work: the browser does not let the page read `news.json` and `sources.json` from a `file://` address, so the page then only says "Kunde inte hämta nyheter. Försök igen senare." (This is by design: the design only describes the local server, R12.1.) The saved copy of the last list (local storage, per address, so use the same address and port every time) is shown, with a notice, when `news.json` cannot be loaded but `sources.json` can; if `sources.json` cannot be loaded either, the page cannot check the links and shows the failure text.

What the command does:
- Reads and checks `sources.json` and `politics-keywords.json`. If either is invalid, the command prints a message on stderr, exits with code 1 and writes nothing. Nothing else makes the build fail: a source that cannot be fetched never does (R6.4).
- For each source that is enabled and has `fetchedBy: build` (today only SVT): reads the host's `/robots.txt` once per run, and does not fetch a path that is disallowed for the user agent `GithubAutoPlay-news-reader/1.0` (status `blocked-by-robots`). A `robots.txt` that answers 404 or another 4xx except 429 means no rules, so the feed is fetched. A group in `robots.txt` names us by `GithubAutoPlay-news-reader` or by the full agent line with `/1.0` (case does not matter), a leading byte order mark is ignored, and percent-encoded unreserved characters (`%7E` and `~`) are treated as the same, as are raw non-ASCII characters and their UTF-8 percent-encoding (`/ä` and `/%C3%A4`). One that cannot be read (timeout, network error, 5xx, 429, over 2 MiB, not UTF-8 text, redirect to another host) means the source is not fetched and gets the status `error`, so the 24-hour fallback below applies. Then it makes one request for the feed, with that User-Agent, no cookies, a timeout of 15 seconds, redirects only to https addresses on the source's `allowedHosts`, and a limit of 2 MiB that is enforced while the body is downloaded, and a total limit of 60 seconds for the whole download (checked after every piece of data that arrives, so a server that sends one byte at a time cannot keep the build waiting). Every failure inside the fetch layer (invalid address, broken connection, incomplete body) is a `FetchError`, so it is a failed source and never a crash. Sources with `enabled: false` are not fetched and not listed. Sources with `fetchedBy: browser` (Sveriges Radio) are never fetched, never listed and never stored: the build refuses to run if such a source reaches the fetch step by mistake, and `sources.json` is invalid if a browser source does not have `storageAllowed: false`.
- Writes `build/news.json` (UTF-8): `generatedAt`, `generatedAtDisplay`, `sources` (for each build source `id`, `name`, `status`, `lastSuccess`, `itemCount`, and a short `message` when the status is not `ok`: fixed text or the name of an exception class, never feed content) and `items` (the seven fields of R1.1). Then it copies the content of `site/` (without its `tests` folder; symbolic links inside `site/` are skipped, not followed), `sources.json` and `politics-keywords.json` into `build/`. The page files are therefore at the top of `build/`, next to `news.json`.
- A source that fails (network error, status other than 200, redirect to another host, response over 2 MiB, not RSS 2.0, a feed with no items, or a selection error such as the not yet supported `categoryFilter` method) gets the status `error` and a message, and the build goes on. If the previous `news.json` has items of that source and the source's `lastSuccess` there is less than 24 hours old, those items are kept, except items published more than 7 days before now (R5.2); after 24 hours all of them are dropped. `lastSuccess` keeps the time of the last real success. A feed that is fetched fine but has no politics item is `ok` with `itemCount` 0. Items of a source that is blocked by robots.txt are not kept.
- The previous file is `build/news.json` if it exists (read before it is overwritten, so the fallback works locally), or the file named by `--previous <file>`. A missing or unreadable previous file means no fallback.
- The output folder may not be the project folder, `site/` or a folder inside it, or a folder that holds the project (compared by the real path, so spelling, case and links do not help), and it may not be a symbolic link (a symbolic link `site/` is followed for this check, and a new folder inside `site/` is refused too). The build also refuses to write when `news.json`, `news.json.tmp` or any copied file (or a folder on the way) in the output folder is a symbolic link: nothing is written through links and nothing is written at all in that case. Every file is written to a temporary file next to its target and renamed over it, so a hard link to an old file keeps its old content. Running the build twice gives the same files. Files that were once copied from `site/` and later removed there stay in `build/` until you delete the folder.

The tests cover all of this with a fake fetch layer. They never fetch a real site, so **a check against the real SVT feed is done by the owner or manager** (see step S8 of the design): run the command above on a machine with internet access, look at the status line for `svt` and at `build/news.json`, and judge how well the keyword list selects politics (K6). That check also confirms the real robots.txt answer, the host of the item links (Q2) and that the 15-second timeout and 2 MiB limit are enough for the real feed.

## Run the tests locally
Needs Python 3.10 or newer and Node.js 18 or newer. From this folder (`node --test` finds the `*.test.mjs` files by itself, so run it with no arguments; passing a folder name such as `site/tests` does not work on Node 22):

```
python -m pip install -r requirements.txt
python -m pytest
node --test
```

From the repository root, `bash scripts/check.sh applications/news-reader` runs the Python tests together with the other checks. The tests need no network.
